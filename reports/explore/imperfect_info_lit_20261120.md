## 0. 一页结论

1. **皇室战争的两份报告（`daybreak_cr_20261119.md` / `firstlight_cr_20261119.md`）在"如何赢"上可搬，
   但在"如何对付隐藏手牌"上几乎不可搬。** CR 的隐蔽信息是**可推断且快速收敛**的：8 张牌、确定性循环，
   打两轮基本就知道对手手里有什么——所以两个仓都明确不读对手手牌，只保留"已出牌 + 回手时间"，
   daybreak 甚至故意保留对手圣水精确值。七圣是 30 张牌库 / 5 张手牌 / 8 骰，**同一条"忽略"策略在这里代价高得多**。
2. **文献里唯一有干净消融的支持"特权信息"的做法，是给 critic 不给 actor**：PerfectDou 的 PTIE
   （NeurIPS 2022）在同一预算下，critic 看全部手牌比不看高 **+3.8pp 胜率**（0.524 vs 0.486），
   而同文脚注明确指出**特权信息进到"要出牌的网"里会让 DouZero"以作弊风格打牌"**。
   这正好解释了 daybreak 的负面结果（他们把对手手牌喂给 PPO critic，解释方差反而低于不特权的 IL value 头）：
   特权 critic 不是万灵药，**只有在价值头本身是瓶颈时才有收益**。
3. **隐藏手牌的"天花板"很低**：炉石同类工作里，把对手**牌库**直接给观测（比给手牌还强）只买到
   **73.6% → 80.2%（+5.5pp）**；而两个 30 张牌库量级的 SOTA agent（ByteRL、ByteDance 炉石）**根本不建模对手手牌**。
   所以"学一个手牌后验塞进策略输入"在文献里**没有可复现的正向证据**，别把它当主线。
4. **有证据的正确用法是"用来给搜索定权"，不是"当特征"**：Skat 的 policy-based inference 用
   `P(对手观测到的出牌 | 世界)` 给确定化（determinization）加权，而不是把后验拼进网络。
   我们的信息集其实**小到可以枚举**（剩余 ~25 张取 5，最多 ~5.3 万），这是比 BAD（3000 粒子）
   或 AlphaZe\*\*（3–10 粒子）更奢侈的条件——枚举 + 精确加权比采样更省。
5. **搜索侧近年最匹配我们形态的是 Obscuro（ICLR 2026，已核实）**：不学习，纯搜索——从"与公开信息一致的位置集合"
   里**采样几百个世界**、用 KLUSS 建子博弈、one-sided GT-CFR + PCFR+ 求解、叶子用现成的完美信息评估函数。
   它的消融很直白：关掉 KLUSS 85.1%→58.0%，关掉 one-sided GT-CFR →53.3%。**叶子评估器可以用我们的脚本专家/启发式代替**，
   不需要价值网——这对 D23/D26 之后"价值头不可信"的现状是决定性的。
6. **本仓已经领先的地方**：`train/belief_head.py` 已经在预测**对手手牌 + 剩余牌库的卡片后验 + 手牌数 + 爆发就绪数**，
   标签来自上帝视角、输入只来自 `player_view`（`reps/observation_encoder.py:419`）。也就是说
   **表示层已经做到了 DouZero+/Skat 那一步**，缺的不是网络，是（a）它到底准不准的**校准测量**，
   （b）把它接进搜索的**用法**。
7. **排序建议**（与 D23/D26 的前置条件一致）：
   **① belief 校准测量（0 新对局）→ ② PTIE 特权 critic（训练侧，actor 不变）→ ③ 信仰加权确定化 + Obscuro 式子博弈搜索
   （CPU，叶子用脚本专家）→ ④ WEVA 式动作抽象（如果 ③ 的宽度撑不住）**。
   ①②③ 都不需要改观测，因此不触碰信息泄漏门禁。

## 1. 为什么 CR 的经验在这条轴上失效

| 维度 | 皇室战争（两份报告） | 七圣召唤（本仓） |
|---|---|---|
| 隐藏状态来源 | 对手 8 张牌 + 确定性循环 | 对手 5 张手牌，来自 30 张牌库；牌库顺序未知 |
| 可推断性 | **高**：打完一轮循环就基本还原手牌；两个仓都实现了公开 tracker | **中**：只能从"已打出/已消耗的骰子/公开调度"反推，信息集随回合变大再变小 |
| 对手手牌是否进网络 | 都**不进**；FirstLight 只给"已揭示牌 + 未知比例"，圣水用**区间 + 不确定度** | 我们**有一个专门的 belief 头**在预测它（标签来自上帝视角） |
| 特权 critic | daybreak 试过（看对手手牌）→ **更差**；FirstLight 明确不特权 | 未做；但我们的价值头正是 D23/D26 认定的瓶颈 → 值得做 |
| 主要动作空间 | 5 tick × 卡槽 × 576 格 | 每回合 ~10³ 个 option 序列，分层（51 类高层动作） |
| 搜索可行性 | 实时，时间预算毫秒级 | 回合制，可给到秒级；引擎 4k 局/h CPU |

一句话：**CR 的"不完全信息"是工程噪声，七圣的"不完全信息"是核心难点**。所以 CR 报告里
"别管隐藏信息、把工程做扎实"的结论，在我们这里要反过来：**隐藏信息必须显式建模，但要用在有证据的用法上**。

## 2. 文献地图（按证据强度排序）

### 2.1 特权信息：只给 critic，不给 actor —— 最强证据

- **PerfectDou / PTIE**（NeurIPS 2022，arXiv:2203.16406）**[已核实]**
  perfect-training-imperfect-execution：价值网看全局（三家手牌 + 最小出牌步数），策略网只看公开信息。
  同预算（1e9 样本）对 DouZero(1e10) 消融：**PerfectDou 0.524 / ImperfectDou 0.486 / 无 node reward 0.540 /
  vanilla PPO 0.346**（Table 4）。→ 特权 critic 单独贡献约 **+3.8pp**；去掉特权 + 去掉中间奖励，PPO 直接崩到 0.35。
  脚注原文：**"DouZero cannot acquire any perfect-information feature since it will play in a cheating style if so."**
- **RARSMSDou**（IEEE ToG 2023）**[转述]**：同一配方（特权信息进 PPO 的 critic），报告对 DouZero **WP 0.582**。
- **OADMCDou**（IJCAI 2024）**[转述]**：oracle guiding + 自适应 DMC。
- **Suphx**（arXiv:2003.13590）**[转述]**：另一种写法——**perfect-feature dropout**，把全局信息在训练中逐渐从 actor 里退火掉。
  没有独立消融数字。
- **反证（同等重要）**：daybreak-cr 把对手手牌喂给 PPO critic，解释方差 0.186/0.278，
  **低于不特权的 IL value 头 0.274/0.321**；单独换 critic 重启后首个门禁 49.6% 被停。
  → 结论不是"特权 critic 有用"，而是**"特权 critic 只在价值头本身欠拟合时有用"**。我们正处在这个状态（D23/D26）。

### 2.2 不完全信息搜索：不枚举公共知识，采样世界 + 局部求解

- **Obscuro / FoW chess**（ICLR 2026，arXiv:2506.01242）**[已核实]**
  维护全部可能局面集合 `P`（|P| ≤ 10⁶），但每步只**随机采样几百个** `I ⊆ P` 建子博弈；
  **KLUSS**（knowledge-limited unfrozen subgame solving）裁掉"大家都知道不可能是真"的高阶知识区；
  **one-sided GT-CFR**（只让探索方扰动）+ **PCFR+**；叶子用**现成的完美信息评估函数**（Stockfish）。
  对前 SOTA 85.1%；消融：去 purification 70.2%，**去 KLUSS 58.0%**，**去 one-sided GT-CFR 53.3%**；
  换一个"只看子力+可见格"的傻瓜评估器仍有 **55.0%** 胜前 SOTA。
  → **叶子评估器不需要是学习出来的**：这个消融直接支持"用我们的脚本专家当叶子评估"。
- **Student of Games / GT-CFR**（Science Advances 2023，arXiv:2112.03178）**[转述]**
  增量扩树 + CFR 平均策略，避免枚举公共树。注：**"Player of Games" 不是另一篇论文**，是同一预印本的早期标题，
  引用时不要当成两篇。
- **Update Equivalence Framework**（ICLR 2024，arXiv:2304.13138）**[转述]**
  用"复制一步 last-iterate learner"代替解子博弈；在 Hanabi 上**匹配 PBS 搜索但搜索时间少两个数量级**。
  → 隐藏信息大、搜索预算小时，便宜的计划方法可能优于昂贵的均衡求解。
- **深度受限求解**（Brown/Sandholm/Amos 2018；Kovařík et al., AIJ 2023）**[转述]**
  多值状态（multi-valued states）：在深度上限给对手一组"续打策略"选择，**不需要价值网**。
  对我们最实用的一档是：价值网换成"脚本专家 + k 个扰动版本"的策略组合。

### 2.3 均衡计算在小预算下的可行做法

- **WEVA**（arXiv:2605.10900，2026）**[转述]**：先跑 **10 次**普通 CFR 拿到每个节点的 EV，深度加权后
  k-means++ 聚成 K 个桶，再在抽象博弈上求解；K=200 时相对 equity/rank 抽象把可利用度降最多 **80%**，
  额外开销 ~2.7%，**纯 CPU、无需神经网络**。→ 如果我们真要重开 CFR，这是第一个该抄的抽象方法。
- **RL-CFR**（ICML 2024，arXiv:2403.04344）**[转述]**：让 RL 学一个**动作子集**（abstraction），再在其上跑 CFR；
  在 HUNL 上超过 ReBeL 复现。→ 直接对应我们"每回合 10³ option、不能全宽"的问题。
- **VR-MCCFR**（AAAI 2019）**[转述]**：baseline-corrected 采样，纯 CPU 方差缩减，可与上面任意一个组合。
- **WEVA/RL-CFR 的共同前提**：得有一个能跑 CFR 的树。我们已有 `train/cfr_solver.py`（engine-free MCCFR），
  只缺"树怎么长"和"叶子怎么估值"。

### 2.4 手牌推断：表示与用法

- **DouZero**（ICML 2021，arXiv:2106.06135）**[转述]**：**不建模对手手牌**，只给"其余玩家手牌并集"计数 + 最近 15 步 LSTM。
- **DouZero+**（arXiv:2204.02558）**[转述]**：多头分类器预测"下家每个点数还有几张"，拼进状态-动作特征；
  提升只以曲线呈现，**未给可比的 head-to-head 胜率**，且主要在农民侧。
- **Skat policy-based inference**（AAAI 2019，10.1609/aaai.v33i01.33011158）**[转述]**：
  用"对手按某策略会打出这张牌"的似然给确定化加权，而不是把后验当特征；摘要称"大幅提升"但无数字。
- **History Filtering**（NeurIPS 2023）**[转述]**：证明**一般情况下构造一个与观测一致的完整历史是不可行的**，
  给出可高效枚举的充要条件，并针对吃墩类游戏给 MCMC（RingSwap）采样器。
- **Potential Outcome Isomorphism**（arXiv:2403.11486，2024）**[转述]**：抽象方法学；关键警告——
  **抽象对手的动作空间会引入"对手只在我抽象里出牌"的病态**；提高己方抽象分辨率只有在对手动作空间不抽象时才降可利用度。
- **炉石 oracle 对照**（arXiv:2303.05197）**[转述]**：把对手**牌库**直接进观测，73.6%→80.2%（+5.5pp）——
  这是"知道隐藏信息"的**上界**，而且注意：给的是牌库不是手牌，等于连抽牌顺序都告诉它。

## 4. 可执行方案（CPU-only，按证据强度排序）

### B1. belief 校准测量（0 新对局，0 训练）

- 数据：任意现有 store（`data/store/*.pt` 里带 `b_hand`/`b_deck` 标签的那批）。
- 指标：对手手牌后验的 **top-k 命中率 / log-loss / Brier**，对比两个基线：
  (a) 均匀先验（只用剩余牌库计数），(b) "已出牌反推"的规则先验（`reps/public_state`）。
- 判定：**只有显著优于 (b)** 才允许进入 B2/B3。否则 belief 头只是又一个 val_acc 幻觉（D25 的教训）。
- 成本：分钟级。

### B2. PTIE 特权 critic（训练侧，actor 不动）

- 做法：给 value 头一段独立的 **full_state 输入分支**（对手手牌 + 牌库 order 的集合特征），
  actor 的输入保持 `player_view` 不变；值损失照旧，策略梯度用该 critic 的 baseline。
- 为什么现在做：文献里它单独值 +3.8pp，**且**我们的价值头正是被判定为"没有区分度"的那个（D23/D26）。
- 为什么安全：`tests/test_info_leak.py` 只约束**策略输入**；特权输入必须走独立的 value 分支，
  并在 checkpoints 里标记 `privileged_value=true`，`neural:` 推理路径不得加载该分支。
- 判定：先过 B1 的同款"真值测试"（`replay_branch` 在 200 个位置上 fork 求均值），
  **value Brier 明显优于常数 0.25** 才算修好；之后再谈搜索重开。
- 成本：~1 天 + 1 次训练（CPU/小网）+ 0.5h 真值测试。

### B3. 信仰加权确定化 + 脚本专家叶子（Obscuro 骨架的迷你版）

- 做法（灵感：Skat PBI + Obscuro 的 `I ⊆ P` + 深度受限求解的多值状态）：
  1. `reps.belief.sample_belief_roots` 按 belief 头 + 公开出牌约束采样 **K=64–256** 个世界
     （我们的信息集可枚举，可先做**无放回**加权采样，甚至精确枚举小状态）；
  2. 对每个世界，用现有 `envs.fork_bridge` 在 `is_resumable()` 边界 fork，注入候选动作；
  3. 叶子不用价值网，用**脚本专家打完的胜负**（或 `heuristic` 的 1-ply 评估）；
  4. 按"该世界下对手打出已观测动作的似然"给世界加权（PBI），取加权平均。
- 与已失败的 A4/D23 的区别：那次是**蒸馏搜索到策略网**（软标签劣于硬标签，D23），
  这次是**只用搜索选动作**，不蒸馏。
- 判定：与同 deck 认证臂做 400 配对局；`CI_low ≥ −0.02` 且点估计 >0 才进阶梯。
- 成本：K×candidates 局/决策；K=64、候选 8、搜索每 4 步一次 → 约 10–20× 对局数，CPU 可承受。

### B4. WEVA 式动作抽象（仅当 B3 的宽度撑不住）

- 先跑 10 次 CFR 拿节点 EV → k-means 聚成 K≈200 个桶 → 在桶上求解。纯 CPU、无需网络。
- 前置：B3 已证明"搜索本身有用"；否则抽象只是把无效搜索变便宜。

## 5. 明确不做（有证据）

| 不做 | 证据 |
|---|---|
| **把预测手牌拼进策略输入** | 2 人 30 张牌库量级**没有任何**可复现的正向 head-to-head 结果；两个 SOTA 炉石/斗地主 agent 都不建模手牌 |
| 全宽 1-ply 搜索 | 宽度本身有害、深度才付钱（PokaiTrainer 消融；SePoT 显示 depth-1 劣于 2–3） |
| 抽象对手的动作空间 | Potential Outcome Isomorphism：会让"对手只在我抽象里出牌"，可利用度反升 |
| 再投一次"搜索蒸馏" | D23 + daybreak 独立复现（搜索玩家强 20pp，蒸馏只带走 ~10%） |
| 用特权信息训练**策略**网 | PerfectDou 脚注：会以作弊风格打牌；我们的 info-leak 门禁也会拦 |
| 靠"给 critic 喂特权"当万能药 | daybreak 实测更差；只在价值头欠拟合时才有 B2 的收益 |

## 6. 验证记录与未核实项

**本报告已核实的原文**（主会话直接读 proceedings/arXiv 页面）：
- PerfectDou NeurIPS 2022 Table 4 的四个变体数字、PTIE 定义、以及"cheating style"脚注 —— 与 §2.1 一致。
- Obscuro（ICLR 2026，arXiv:2506.01242）：`|P| ≤ 10⁶`、采样 `I` 为"a few hundred"、KLUSS、one-sided GT-CFR、
  PCFR+、Stockfish 叶子、以及 6 组消融数字（85.1 / 70.2 / 58.0 / 53.3 / 73.2 / 81.9 / 55.0）—— 与 §2.2 一致。

**转述未核实**（引用前请自查）：DouZero+ 的具体增幅、Skat PBI 的量化增益、Suphx oracle-guiding 的独立消融、
RARSMSDou 的 0.582、WEVA 的 80%/2.7%、RL-CFR 的具体胜率、History Filtering 的充要条件细节、
Potential Outcome Isomorphism 的定理编号。

**不存在 / 需警惕**：
- "ARCTIC"（文献 lane 未找到任何同名论文，疑为 DREAM/ESCHER 线的误记）——**不要引用**。
- "Player of Games" 与 "Student of Games" 是同一预印本 arXiv:2112.03178 的前后标题，**不是两篇**。
