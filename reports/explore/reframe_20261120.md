## 1. 形式化（2026-11-20 修订）

**博弈**：两人零和、有限期、不完全信息。**对手是 20 个固定脚本，不是理性体。**

### 1.1 当前研究的游戏模型

- **AI 侧只用一副牌 `Ax`**：同一副牌、同一个模型，打完全部 20 个对手。
- **20 个脚本对手各用其脚本对应的牌组 `A1..A20`**（`agents/scripted/registry.py` 的 20 套），
  即"一个固定 AI 牌组 × 20 个不同牌组的脚本专家"。
- 先手/后手按配对种子各打一次（双方各半），沿用 `docs/EVAL_PROTOCOL.md`。

**由此带来的口径要求**：

1. **牌组不对称是结构性的**：`Ax` 对某些 `Ai` 天然占优、对另一些天然劣势。
   所以 **pooled 胜率不能单独作为结论**，必须逐对手报；跨 deck 比较只在同一 `Ax` 内成立。
2. **唯一干净的对照是 `expert:Ax`**——同一个牌组的脚本专家，对同一个 20 套池。
   主指标 = 配对 Δ（我方 − `expert:Ax`，同种子、双方各打一次、只算干净局）。
   这也是 `scripts/eval_protocol.py --baseline expert:<deck>` 的既有口径。
3. 换 `Ax` = 换一个新实验，不能与前一个 `Ax` 的数字横比（D24 的 deck confound）。

> 附注（2026-11-20 实测，与本节结论无关但值得记录）：脚本专家的规则是**绑定自家牌组**写的
> （`agents/scripted/deck_rules/<slug>.py`）。若强行让 20 个专家改打同一副外地牌组，
> 卡牌专属规则全部失效、只剩通用规则链 + `style`/`switch_hp_threshold` 两个旋钮，
> 20 条决策序列会塌缩成 **13 条**（且 fallbacks=0，即不会出非法动作）。
> 所以"20 个对手"的多样性**依赖它们各自打自己的牌组**，这也是本节的设定。

### 1.2 状态与观测

- **公开状态 `s_pub`**：阶段、回合、当前行动方、双方场上角色的 id/血量/充能/元素附着/装备/状态、
  召唤物、支援区、是否宣布结束、**双方手牌张数**、**双方骰子个数**、所有**已打出的牌**。
- **隐藏状态 `x`**（引擎在 `notification.state` 里就已抹掉，实测：对手骰子全 0）：
  对手手牌**身份**、对手牌库**身份与顺序**、对手骰子**面值**。
- **己方私有**：己方手牌身份（≤**10** 张；初始 5，`ATTR_STATE_CONFIG_INITIAL_HANDS_COUNT=5`、
  `MAX_HANDS_COUNT=10`）、己方骰子面值。
- **己方牌库顺序同样未知**：玩家知道自己牌库的**多重集**（自己组的牌减去已抽/已消耗），
  但不知道抽牌顺序。我们的编码器把己方牌库按 `definition_id` 排序，等价于只保留多重集——
  这个处理是对的，但**必须在文档里写明它是"多重集"而不是"序列"**。
- **历史信息（双方）**：完整动作序列（谁、什么动作、什么目标、用了哪些骰子、公开结算结果），
  是**与 `s_pub` 并列的独立观测通道**，不是可推导的附属物。
  编码器**设计上**预留了 32 个 history token，但**当前所有调用点都传 `history=()`**
  （`agents/neural.py`、`train/data.py`、`train/distill.py`、`train/batched_inference.py`、
  `train/resolver.py`），实测 store 样本 `history token = 0`。即这条通道**现在是空的**，
  属于待补的输入缺口，不能写成"已承载"。详见 `model_spec_20261120.md §3.1`。

于是观测 `o_t = (s_pub_t, 己方私有_t, history_{≤t})`，训练期额外可见 `x_t`（只进 critic）。

### 1.3 关键结论：这是 **best response**，不是 equilibrium

对手是固定的脚本，不会针对我们调整。因此：

- **不需要 Nash / 不需要 CFR / 不需要可利用度。** 均衡解是"对任何对手都不被剥削"，
  我们只需要"对这 20 个固定脚本尽可能强"。
- 正确的解概念是 **已知对手策略下的 POMDP 最优策略**（对手策略是环境的一部分）。
- 这解释了为什么 n=800 的 MCCFR 显著更差：它解的是"对这个 rollout 策略的均衡"，
  而该策略既不等于真实对手也不稳定；8–16 次外采样在 ~10³ 动作上远未收敛，
  **等于用一个欠收敛的均衡覆盖掉一个很强的专家先验**。
- 代价：对固定脚本的最优策略**不可迁移到人类**。要迁移必须换成多样的对手分布（league）。

## 2. 旧实现为什么不算"论文方法"

| 论文要素 | 我们的实现 | 差距 |
|---|---|---|
| 公共信念状态 | `reps.belief` 有（可枚举/可加权） | 只用于搜索根，**从未进入策略** |
| 解概念 | CFR / fork-MC 求近似均衡 | 对手固定，**解错了对象** |
| 收敛诊断 | 无 | 8–16 iter 就上评测，没有"距解多远"的度量 |
| 动作抽象 | 全宽候选（含 base） | 无 WEVA / RL-CFR 式抽象，节点宽度不可控 |
| 价值 | 终局胜负 or 修好的 value head | 无真值校准，叶值方差压倒信号 |
| 对手模型 | rollout 用同 deck 专家 | 等于"假设对手也会这么打"，与真实对手不符 |

## 3. 新刻画下的方法（按证据强度排序）

1. **策略直接从公开观测出招**（`π(a | o, h)`），测试期**不做搜索**。
2. **PTIE 特权 critic**：价值网络额外吃"对手真实手牌/牌库"（仅训练期），策略网络永远只看公开观测。
   证据：PerfectDou 同预算 +3.8pp；特权信息进 actor 会让 DouZero"以作弊风格打牌"。
3. **belief 头作为辅助目标 + critic 的输入**，**不作为策略输入**（无任何 2 人 30 张牌库的可复现正证据）。
4. **league / PFSP 自博弈**：当我们在池上稳定超过专家后，用它防止对 20 套脚本过拟合。
5. 价值必须先过**真值测试**（`train/replay_branch` 在固定位置 fork 求均值）——这是所有价值相关
   工作的前置，也是 D23/D26 留下的未完成项。

## 5. 第一里程碑（可判定、CPU）

**M-A：特权 critic 的价值真值测试。**

1. 用 `train/replay_branch` 在 200 个位置上各 fork 8 局求均值，得到该位置的经验胜率（真值）。
2. 在同一批位置上比较三个估计器：常数 0.5 / 现有 value 头 / 特权 critic。
3. 判定：特权 critic 的 Brier 显著优于现有 value 头，且两者都优于常数 0.25 → 继续；
   否则价值路线整体冻结，先修数据与标签。

**为什么先做这个**：D23/D26 之后，"价值能不能用"是搜索、PTIE、league 共同的闸门；
它同时是 0 新采集（现有 store + replay）就能回答的问题。

- 把 belief 当策略输入；
- 为"均衡"做优化（对手固定，解概念不适用）。
